# Make the server the single source for lines and stations

Date: 2026-07-17
Author: Petros Dhespollari
Status: decided, not started. Blocks Thessaloniki reaching the apps.

## The problem

Line and station data exists **twice**, and the two copies are joined by a script
that no longer runs.

- **The apps read a legacy seed.** `LineRepositoryImpl` and `DataSeeder` both read
  `files/seed/lines.json`. That file is a flat array, generated by
  `scripts/sync-ios-transit-seed.mjs` **from hardcoded Swift** in
  `iosApp/.../TransitData.swift`. iOS itself reads the same hardcoded Swift
  directly.
- **The server generates a different file.** `snapshot-api-to-seed.py` writes only
  `schedules-v2/` (schedules, offsets, fares, icons, announcements, shapes). It
  **never writes `seed/lines.json`**. The generator's `lines.json` lives under
  `schedules-v2/` and nothing reads it for the line list.
- **The bridge is broken.** `sync-ios-transit-seed.mjs` points at
  `iosApp/iosApp/Models/TransitData.swift`, which has not existed since the June
  2026 iOS restructure moved it to `iosApp/iosApp/Core/Schedule/`. Running it
  crashes with ENOENT. The legacy seed was last touched by a manual commit.

So the DB is the source of truth for schedules but **hardcoded Swift is the source
of truth for lines and stations**, and there is currently no working path between
them.

This was discovered while wiring Thessaloniki: seeding TM1/TM2 into the Pi and
regenerating produces `schedules-v2/lines.json` containing them, while the apps
still list ten Athens lines, because that is what the legacy seed says.

## The decision

**The server DB becomes the single source of truth for lines and stations.** The
apps read `schedules-v2/lines.json`. The legacy seed and the Swift-as-source
script are retired.

Why:

- **City 3 must be a data exercise.** The whole point of `region` is that adding a
  city means adding rows, not editing Swift by hand in a file that then has to be
  transcribed into JSON by a script nobody runs.
- **Two sources drift.** They already have: the generator now emits `region` and
  `status`, and the legacy seed cannot carry them, so the honesty guarantee for
  Thessaloniki Line 2 would silently never reach a client.
- **The broken script is the tell.** A bridge that has been dead for a month
  without anyone noticing is a bridge nobody should depend on.

Rejected: repointing the script at the new Swift path. It works today and is
smaller, but it keeps lines defined in two places and makes every future city a
manual Swift edit.

## Shape of the work

1. **Schema.** `schedules-v2/lines.json` is `{version, updatedAt, lines:[...]}`;
   the legacy seed is a flat `[...]`. Same per-line camelCase shape otherwise, so
   the DTO mostly survives. `SeedLine` gains `region` and `status`; give them
   defaults (`athens`, `operational`) so a stale bundle still parses.
2. **KMP.** Point `LineRepositoryImpl` and `DataSeeder` at
   `files/seed/schedules-v2/lines.json`. Add `region` + `status` to the `Line`
   domain model and to `line_entity` (SQLDelight migration). Same for `Station` +
   `region`.
3. **iOS.** `SyrmosData.lines` is a hardcoded Swift array. It should load from
   `seed-schedules-v2/lines.json`, which is already bundled and already copied by
   `snapshot-api-to-seed.py`.
4. **Web.** `web-map.js` reads `files/seed/lines.json` + `stations.json`; point it
   at the schedules-v2 payload.
5. **Retire.** Delete `sync-ios-transit-seed.mjs` and the legacy
   `seed/lines.json` / `stations.json` once nothing reads them.
6. **Honour `status`.** Projector, simulator, home hero, track-picker and
   last-train skip non-operational lines; the map draws them greyed.

Safety: every KMP `Json {}` sets `ignoreUnknownKeys = true` and Swift's
`Decodable` ignores unknown keys, verified across the codebase. New fields are
additive and cannot break shipped 1.2.0 / 1.2.2.

## Why this blocks Thessaloniki

Until it lands, seeding the Pi changes nothing the user sees: the apps would keep
listing ten Athens lines. Deploying the seed now would only put Thessaloniki into
`schedules-v2/`, where the line list is ignored.

The seed and the generator work are already done and pushed. This is the missing
piece between them and a user.
