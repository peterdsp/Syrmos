## 2. Parity discipline

- One pure transform per rule, mirrored across web/iOS/Android, asserted against the same
  `fixtures/journeys/` inputs (never three independently invented scenarios).
- IDs stable across recomputation; never match by list index or display name (prompt 7.1).
- `null` means unknown, never zero. All schedule evaluation in `Europe/Athens` with stored absolute
  instants + operator service date; do not assume 24h days.
- Design dimensions flow from the token source + `generate_tokens.py`, not hand-copied per platform.

### 2.1 De-duplication and grouping is a hard invariant (all surfaces)

No list of departures, options, saved journeys, or airport services may ever show the same thing
twice. Concretely, on every client and every surface:

- **Group by (line, destination).** One card per line+destination, with the next N times as a
  dominant countdown plus a "Then …" tail. Never a stack of one-time-each rows for the same line to
  the same place (the exact defect visible in the shipped Airport hub: `A1 Syntagma 04:00`,
  `A1 Syntagma 04:00`, `A1 Syntagma 05:00` as three rows). This already exists as a pure transform
  per client (`SyrmosDepartures.groupDepartures` on web, `SyrmosDeparturesGrouping` on Android,
  `AirportServiceRows`/board grouping on iOS). New 3.0 lists must route through the same transform,
  not re-render raw rows.
- **Drop exact duplicates.** Identical `(line, destination, time)` collapses to one, including the
  case where two source ids project one physical train (e.g. `M3` and `M3_AIR`, deduped by time).
- **Deduplicate itineraries** by identical leg sequence before ranking (prompt 7.2) and never pad to
  three options with near-identical routes.
- **Verify it.** Extend `fixtures/journeys/` (and reuse the existing departures-grouping tests) with
  explicit duplicate inputs: repeated destination, same-time duplicate, dual-id train, duplicate GPS
  event (prompt 7.4 idempotency). The same duplicate input must collapse identically on web (node),
  Kotlin, and iOS. iOS already pins this in `AirportServiceTests`
  (`testMetroDuplicatesCollapseByTime`, `testSuburbanDedupAndCap`); the requirement is to keep that
  guarantee everywhere a 3.0 list is introduced.

## 3. Local verification tiers available in this environment

Confirmed available: JDK17 + Android SDK, Xcode, node, curl to the live API. So:
`node --test web-tests/*.test.js`; `./gradlew :core:domain:allTests`; `./gradlew :androidApp:assembleDebug`;
`xcodebuild -list -project iosApp/Syrmos.xcodeproj` + XCTest on an available simulator;
`python3 scripts/verify-bundles.py`. Deployment commands are never run as tests.
