# Syrmos 3.0.2 plan

Status: draft, 2026-10-27. Target: 3.0.2 (iOS 3.0.2, Android 3.0.2 versionCode 271). Web is desktop only, so web gets the read-only parts (closures, broadcasts banner) and none of the GPS or calendar features.

Scope, in the owner's numbering:

1. Smart "next train" notification when near a station
2. Calendar flight: leave-by notification so the rider is at the airport 1.5 to 2 h early
3. Same for every calendar event with a location, with a per-event buffer algorithm
4. Private admin console to broadcast notifications and close stations, without an app release
5. Real station closures: closed in the UI, time window, replacement bus info
6. Ad / guerrilla marketing research (stickers, QR, visuals)

## 1. Smart next-train notification near a station

### Behaviour
When the rider comes within 1 km of a station (and is not already on a train), show one notification per direction:

> **Νίκαια** · 6' με τα πόδια
> Αεροδρόμιο: 4', 14' · Δημοτικό Θέατρο: 2', 9'
> Μπορεί το επόμενο για Δουκίσσης Πλακεντίας να έρχεται σε 2', αλλά το μεθεπόμενο είναι σε 10'. Χαλαρά, δεν χρειάζεται να τρέξεις.

### Design
- **Trigger.** iOS: `CLLocationManager` region monitoring (max 20 regions), so monitor the 20 nearest stations and re-pick on significant-location-change. Android: `GeofencingClient` (100 limit, same nearest-N rule) with `GEOFENCE_TRANSITION_DWELL` (about 60 s loiter) to avoid drive-by spam.
- **Guards.** Opt-in toggle (off by default, prompt after the 3rd station view); speed > 25 km/h means skip (in a car or on a train); per-station cooldown 45 min; global max 4/day; quiet hours 23:00 to 07:00; skip if a GO journey is active (GO already guides).
- **Content is computed on device from the offline projector** at trigger time (no network needed). Region entry gives about 10 s of background time, enough for a projection. Uses the existing grouping transform (line, destination) and next 2 times per direction.
- **Walking time.** `distance * 1.3 detour / 80 m/min`, rounded up, minimum 1. Later: use the station entrance coordinates when we have them.
- **Catchphrase engine (`NearbyDepartureCoach`).** One pure function in `core/common` (Kotlin) mirrored in Swift, driven by a shared JSON fixture (the same pattern as `GoGuidance.progress`). Input: walk minutes, next N departures, headway, last-train flag, closure flag. Output: a `CoachCase` enum plus params; the text lives in the String Catalog (iOS) and the Android string resources, with several variants per case picked deterministically by `(stationId, day)` so it does not feel robotic.

| Case | Rule | Example (el) |
|---|---|---|
| `relaxNextOneIsClose` | first missed (dep < walk), second catchable and gap <= 10' | "Το επόμενο φεύγει σε 2', αλλά το μεθεπόμενο είναι σε 10'. Μην αγχώνεσαι." |
| `longGapTakeItEasy` | first missed, second > 10' | "Χάνεις το τωρινό, το επόμενο σε 15'. Ώρα για freddo." |
| `hurry` | 0 < dep - walk <= 2 | "Αν περπατήσεις γρήγορα, το προλαβαίνεις." |
| `comfortable` | dep - walk >= 3 | "Άνετα. Φτάνεις με 3' περιθώριο." |
| `lastTrain` | catchable dep is the last of the night | "Προσοχή: αυτό είναι το τελευταίο για σήμερα." |
| `stationClosed` | item 5 closure active | "Ο σταθμός είναι κλειστός. Λεωφορείο αντικατάστασης κάθε 10'." |

- **Rule: never tell someone to run unsafely.** `hurry` says "walk fast", never "run". Never claim live accuracy when the data is scheduled (label "κατά πρόγραμμα" when not live).

### Work
- `core/common`: `NearbyDepartureCoach.kt` + fixture + tests.
- iOS: `StationGeofenceService.swift` (region set manager), wire into `NotificationService`, Swift mirror + fixture test, String Catalog entries (en/el/sq/it). Needs "Always" location permission: ask contextually, explain in the toggle. Update `Info.plist` usage strings.
- Android: `StationGeofenceManager` + `GeofenceBroadcastReceiver`, `ACCESS_BACKGROUND_LOCATION` flow (Android 10+ requires a separate settings trip), new notification channel `nearby_departures`.
- Settings toggle on both clients, plus privacy policy update (`docs/PRIVACY_POLICY*.md`): location never leaves the device.

## 2 and 3. Calendar leave-by notifications

### Generalise the calendar read
Today only airport keywords match. New `CalendarTripSource` reads all events in the next 48 h with a non-empty location (or a known venue keyword), excluding all-day events and events the user declined.

### Resolve the destination
1. Airport keywords, so ATH or SKG (existing matcher, keep it).
2. Match against station names and aliases (`station_name_aliases`), so the nearest station.
3. Platform geocoder (`CLGeocoder` / Android `Geocoder`), restricted to Attica and Thessaloniki bounding boxes.
4. Unresolved: no notification, show "Add location" hint in the trip list. Never guess.

### Origin
Current GPS at planning time; re-plan when the device wakes (see re-check). Optional saved "Home" later, not required for 3.0.2.

### Buffer algorithm (`ArrivalBufferPolicy`, pure, shared, fixture-tested)
`leaveAt = eventStart - arrivalBuffer - journeyDuration - reliabilityMargin`

| Event type (classified from title/location) | arrivalBuffer |
|---|---|
| Flight (ATH/SKG), default | 120' (setting: 90' Schengen / 120' / 150') |
| Intercity train / ferry (Piraeus, Rafina, Lavrio) | 25' |
| Stadium, concert, theatre (OAKA, Karaiskakis, Megaro, Badminton, known venues list) | 30' |
| Doctor, hospital, exam, interview, public service | 15' |
| Default (meeting, dinner, other) | 5' |

`reliabilityMargin = transfers * 2' + headway/2 of the first leg + 5' if raining (weather card) + 5' if a service alert touches the route`, capped at 20'. Ranking stays comfortable-first (owner decision).

### Notifications (two per event)
- `leaveAt - 15'`: "Σε 15' ξεκίνα για το αεροδρόμιο. M3 από Νίκαια, φτάνεις 2 ώρες πριν την πτήση."
- `leaveAt`: "Ώρα να φύγεις! Η πτήση δεν περιμένει, το M3 όμως έρχεται σε 4'."
- Flight bonus at `leaveAt - 3h`: "Πτήση απόψε. Έλεγξε ότι έχεις διαβατήριο και εισιτήριο μετρό αεροδρομίου (9€)." Fares from the seed, not hardcoded.

### Re-check
iOS `BGAppRefreshTask` plus a silent re-plan when the app opens; Android WorkManager one-off at `leaveAt - 60'` and `- 20'`. If the new `leaveAt` moves by >= 5', reschedule the local notification. If the location is unknown at re-check, keep the earlier schedule.

### Work
- `core/common`: `ArrivalBufferPolicy`, `CalendarEventClassifier` (+ venue list), fixtures, tests. Reuse `LeaveByReminder` engine for scheduling.
- iOS: extend `AirportCalendarStore` into `CalendarTripStore` (EventKit full access is already requested on iOS 17+, confirm the prompt text), scheduler hook.
- Android: generalise `AirportCalendarProvider` (keep the airport path), worker.
- Settings: "Calendar reminders" with per-type toggles and flight buffer choice. All on device, nothing sent to the server.

## 4. Private admin console: broadcasts and closures

### Security (must land first)
The repo is public, so security must come from secrets and network, never obscurity.
- `auth()` currently trusts the `Cf-Access-Authenticated-User-Email` header. Change it to **verify the `Cf-Access-Jwt-Assertion` JWT** (signature against the team certs URL, `aud` tag, expiry) and check the email against an `ADMIN_EMAILS` allowlist in `admin.env`. Without this, anyone reaching the origin directly can spoof the header.
- Confirm the origin only listens on 127.0.0.1 and is reached only through cloudflared; nginx strips any incoming `Cf-Access-*` headers on non-tunnel paths.
- Cloudflare Access policy: only the owner's email, passkey or OTP, short session.
- Every mutating admin route: CSRF token, audit log row (`admin_audit`: who, what, when, payload hash).
- APNs `.p8` key and FCM service account live only in `admin.env` on the Pi, never in git (add to `.gitignore` check and the secrets scan).

### Data model (new migrations)
- `0029_station_closures.sql`: `station_closures(id, station_ids JSON, line_ids JSON, mode TEXT CHECK in ('closed','pass_through','exit_only','entry_only'), starts_at, ends_at NULL = until further notice, reason_en/el/sq/it, replacement_bus JSON NULL {label, from_stop, to_stop, headway_minutes, stops[]}, source ('admin'|'stasy'), status ('draft'|'scheduled'|'active'|'ended'), created_by, created_at)`.
- `0030_broadcasts.sql`: `broadcasts(id, title_*, body_* for 4 langs, audience ('all'|'line:<id>'|'station:<id>'|'region:<athens|thessaloniki>'), send_at, expires_at, deep_link, closure_id NULL, status, sent_count, created_by)`.
- `0031_push_devices.sql`: `push_devices(token_hash, token, platform, lang, topics JSON, created_at, last_seen)`. Anonymous: no account, no location, token only. Delete on APNs 410 / FCM UNREGISTERED.

### Admin UI pages (`/admin/closures`, `/admin/broadcasts`)
- Closure form: pick stations (searchable list), lines, mode, from/until (Athens time, "until further notice" checkbox), reason in Greek, button "Translate" (existing pipeline fills en/sq/it, editable), optional replacement bus, checkbox "also send a push now / at start".
- Broadcast form: text, audience, send now / schedule, preview card per language, dry run (count of targeted devices), send.
- Templates for recurring cases: "28 Oct parade: Syntagma closed from 08:00 by police order, trains pass without stopping until further notice".
- STASY scraper creates **draft** closures from announcements with `affected_station_ids`; the owner approves with one click. Nothing goes live automatically from a scrape.

### Delivery
- **Public read API**: `GET /api/closures` and `GET /api/broadcasts?since=` (cached, ETag). Clients poll on app open, on BG refresh, and in `AlertCheckWorker`. This alone gives "no new release needed" for UI changes.
- **Push** (needs the 3.0.2 client to register): APNs HTTP/2 sent directly from the Pi with the `.p8` key (no Firebase on iOS); FCM HTTP v1 for Android. A systemd timer (`syrmos-broadcasts.timer`, every minute) sends due broadcasts and flips closure status at `starts_at` / `ends_at`. Topics: `all`, `line.M1`, `station.SYN` etc, chosen from the rider's favourites.
- Clients also evaluate the closure window locally, so a closure scheduled for 08:00 flips at 08:00 even offline.

Decision for owner: FCM requires adding the Firebase Messaging dependency to Android. Alternative is UnifiedPush/ntfy (no Google) but much lower reach. Recommendation: FCM.

## 5. Station closures in the product

One `StationClosure` model in `core/model` (Kotlin) + Swift mirror + web, parsed from `/api/closures` and bundled into the seed as a fallback.

- **Projector** (server + 3 clients, keep them in parity): at a `closed` / `pass_through` station during the window, departures are removed from that station's board; the board shows the closure card instead. `pass_through` stations stay on line diagrams marked "trains pass without stopping". `exit_only` / `entry_only` keep departures with a badge. Add schedule invariant tests (`schedule_invariants.py`) that a closure never empties a whole line.
- **Planner**: closed stations are not valid board/alight points; route through the replacement bus leg if defined (headway from `replacement_bus.headway_minutes`), else reroute to the nearest open station + walk.
- **UI**: map station grey (already wired via `stationDisruptions == closure`, now fed by closures too); station sheet banner "Κλειστός 08:00 έως 16:00" or "έως νεωτέρας"; reason text; replacement bus card ("Έκτακτο λεωφορείο κάθε 10', από Σύνταγμα (Αμαλίας) προς Ευαγγελισμό"); Home nearby + favourites badge; GO warns if the active journey touches a closure; widgets show "Closed".
- Chip atomicity rule applies to the "Κλειστός" status chip.
- Ariadne `stationStatus` intent answers from closures first.

## 6. Ad and guerrilla marketing research

Deliverable: `docs/marketing/3.0.2-GROWTH-RESEARCH.md` + a print kit in `docs/marketing/print/`. Proposed content:

### Legal reality first
- Sticking unauthorised stickers inside STASY stations, trains or on public property is defacement (fines, and STASY removes them within days). Paid ad space in the metro is a STASY concession (sold by its advertising contractor), not free. Research step: confirm current rules and contacts, ask STASY/OASA for a free community or startup slot, and ask the Municipality of Athens about free civic noticeboards.
- Free and legal placements: cafés, kiosks (periptera), bakeries and hostels near stations with owner permission; university noticeboards (EKPA, EMP, OPA, AUTh, UniWA); student union and Erasmus offices; coworking spaces; hotel and hostel front desks (airport angle); laptop and bottle stickers handed out (people put them where they want, on their own property).

### Creative directions (all with a tracked QR to `/get-app/?src=<placement>`)
- "Ο συρμός σου σε 3'. Κατέβασε το Syrmos." Big countdown digits, line colours.
- "Μην τρέχεις. Το επόμενο έρχεται." (ties to item 1 coach)
- Airport: "Πτήση στις 10; Φύγε στις 7:12. Θα σου το θυμίσουμε." (ties to items 2 and 3, en version for tourists)
- "Δουλεύει και χωρίς internet, ακόμα και στο τούνελ."
- Sticker shapes: circular line roundels (M1 green, M2 red, M3 blue), a train-countdown die-cut, airport tag shape.

### Channels to research and score (reach, cost, effort)
Reddit r/greece and r/athens, Facebook groups (Erasmus Athens, expats in Athens), Instagram and TikTok Reels (short "made it with 2' to spare" clips), Greek tech press (insomnia.gr, techblog.gr, Kathimerini tech, Lifo), Product Hunt, App Store featuring nomination form, local podcasts, and press kit (`docs/press.html` exists).

### Measure
QR `src` param per placement, server counts redirects (no personal data), compare installs per week. Print run budget: start with 200 stickers + 50 A5 posters, a few tens of euros, scale what works.
